# Installable web app, room list and admin plan

Owner decisions (1 November 2026): web app only (Safari "Add to Home Screen", no App Store, no Apple developer account); players see a list of rooms and tap to join (signed-in players only); an admin app for invites/players, rooms, server status and announcements; hosting on cagdasatici.com via Cloudflare (docs/cloudflare-hosting.md). Local design (D). No new dependencies. Strict TypeScript and strict message schemas apply as everywhere.

One slice per session. Each slice: tests listed below, `pnpm typecheck && pnpm lint && pnpm test && pnpm build`, update docs/tasks.md and its own docs/test-results/<ID>.md, commit, push. Physical iPad checks stay NOT RUN. Stop and report instead of choosing if a listed file is owned by an active lane or an auth/combat check would be bypassed.

sw.js: precache the built asset list for the current `BUILD_ID` (injected at build time by a Vite step or read from `/asset-manifest.json` that the build emits), cache-first for hashed assets, network-first for `/` and the manifest, and **never** touch `/api/*`, `/healthz`, or any WebSocket request. Delete old caches on activate. The invitation fragment (`#invite=`) must still be read and stripped exactly as today.
Tests: unit test for the cache-name and request-routing function (extract it to `apps/client/src/app/swRouting.ts`, pure, no DOM); `tests/browser/install.spec.ts` checks the manifest is linked and valid, sw registers, a second load works with the server's static route stopped, and `/api/version` is never answered from cache. ## WEB2 — `WEB2: add the update button`
Files: new `apps/client/src/app/UpdateWatcher.ts`, `apps/client/src/ui/Lobby.ts` (banner/button), `apps/client/src/main.ts` (wiring), `apps/client/public/sw.js` (waiting state), `tests/unit/update-watcher.test.ts`, `tests/browser/update.spec.ts`.
Behaviour: on launch, on `visibilitychange` to visible and every 10 minutes while the Welcome/Lobby screen is open, call `/api/version` and compare `buildId` with the build the page was loaded from. When they differ, or the service worker reports a waiting worker, show an **Update** button. Tap: tell the waiting worker to `skipWaiting`, then reload on `controllerchange`. Never reload automatically and never show the button during a match (hide it while a room is joined; show it again after leaving). Existing `VERSION_MISMATCH` handling stays as the hard gate: a content-hash or protocol mismatch still blocks joining and now offers the same button. Server-only releases change `buildId` but not the client files; in that case the button reloads the same files harmlessly, so compare the client bundle hash (`/asset-manifest.json`) for the button and `buildId` only for display.
Tests: watcher states (same build, new build, waiting worker, in match, offline, repeated checks without duplicate timers or listeners, dispose); browser test with two builds served in turn.

## WEB3 — `WEB3: list rooms and join with one tap`
Server files: new `apps/server/src/http/roomListRoutes.ts`, `apps/server/src/auth/Services.ts` (nothing new unless needed), `apps/server/src/http/sessionRoutes.ts` (register), `packages/shared/src/rooms.ts` (new strict schemas), `apps/server/src/auth/SparringDirectory.ts` only to add `listed` flag plumbing. Client files: new `apps/client/src/ui/RoomList.ts`, `apps/client/src/app/AppFlow.ts`, `apps/client/src/main.ts`, `apps/client/src/net/RoomClient.ts`.
Contract: `GET /api/rooms` (ordinary session only, same origin and cookie rules as `/api/csrf`, rate limited with the ticket limiter) returns `{ rooms: [{ roomCode, name, kind: "arena"|"sparring", players, capacity, bots }] }`. Only rooms flagged **listed** appear. Arena rooms from `config.roomCodes` are listed by default. Hosted sparring defaults to unlisted; the host setup (SparringSetup) gets a "List this match for other players" toggle; `POST /api/sparring` accepts optional `listed: boolean` (default false) in the strict schema. Never return the room's internal ids, member names beyond a count, or link tokens. Joining a listed sparring room uses the existing `POST /api/join-ticket` after a new `POST /api/sparring/join` that admits an ordinary signed-in session as a non-host guest into the directory (single transaction, same seat limits and 60 s reservation as redeem). Guest authority stays limited to that match.
Tests: real clients — list shows only listed rooms with correct counts; unlisted sparring never appears; full room shows full and join returns 409; two simultaneous joins for the last seat admit one; unauthenticated 401; strict-schema rejection; ordinary FFA/practice regression.

## WEB4 — `WEB4: admin API and login`
Files: new `apps/server/src/admin/AdminAuth.ts`, new `apps/server/src/http/adminRoutes.ts`, `apps/server/src/config/env.ts` (optional `ADMIN_PASSWORD_HASH`, `ADMIN_ENABLED`), `apps/server/src/auth/Services.ts`, `apps/server/src/http/sessionRoutes.ts` (register), `packages/shared/src/admin.ts` (strict schemas), `ops/scripts/admin-hash.ts` (prints a scrypt hash for a password read from stdin), `tests/integration/admin.test.ts`, `tests/unit/admin-auth.test.ts`.
Design: the admin is separate from player sessions and is disabled unless `ADMIN_PASSWORD_HASH` is set. `POST /api/admin/login` with `{password}` checks a scrypt hash with `timingSafeEqual`, rate limited to 5 per minute per IP and 20 per hour globally, with a lockout after repeated failures; success sets `eb_admin` (HttpOnly, SameSite=Strict, Secure unless lanHttp, Path=/api/admin, 2 h absolute, 30 min idle) and returns a CSRF token. All other admin routes need the cookie, CSRF header, allowed origin and the 1 KiB body limit. No admin credential is ever logged; log only "admin login ok/failed". Routes (all under `/api/admin`):
- `GET /status`: build id, protocol version, content hash, uptime, rooms (code, kind, players, bots), player count, last 50 structured log lines (already redacted).
- `GET/POST/DELETE /invites`: list (id, created, expiry, uses left; never tokens), create `{ttlHours,maxUses}` returning the link once, revoke by id.
- `GET /sessions`, `DELETE /sessions/:idPrefix`: list display name, created, last active, revoke (reuse `SessionStore.revokeById`).
- `GET /rooms`, `POST /rooms` (create a named listed arena room), `DELETE /rooms/:code` (disconnect and dispose; use `closeSparringRoom` for sparring), `PATCH /rooms/:code` `{listed}`.
- `GET/PUT /announcement`: one text (max 200 chars) plus optional `expiresAt`; `GET /api/announcement` (public, no auth) returns it for the client banner.
Tests: disabled without a hash; wrong password 401 and rate limit 429; CSRF/origin/cookie checks; ordinary session cookie never authorizes admin; admin cookie never authorizes player routes; every route happy path and unknown id; no token or hash in any response or log.

## WEB5 — `WEB5: admin app screens`
Files: new `apps/client/admin.html` and `apps/client/src/admin/{main.ts,api.ts,screens.ts,admin.css}` (separate Vite entry so the game bundle does not grow; add the entry in `apps/client/vite.config.ts`), `tests/browser/admin.spec.ts`, `tests/unit/admin-api.test.ts`. Served at `/admin`. Screens: Login; Status (auto refresh 5 s while visible); Invites (create with copy link, QR optional, revoke); Players (sessions, revoke); Rooms (create, list toggle, close); Announcement (set, clear). Plain DOM, no new dependencies, large touch targets, works on iPad and desktop. Every listener and timer is cleaned up on screen change. Admin pages are not precached by the service worker and are excluded from the game's install scope (set `Cache-Control: no-store`). Recommended extra protection: Cloudflare Access on `/admin*` (docs/cloudflare-hosting.md).
Tests: fixture API for each screen state (loading, error, empty, 401 returns to Login), double-click suppression, no secret shown after creation, cleanup.
