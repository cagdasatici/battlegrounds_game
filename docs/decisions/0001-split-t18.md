# 0001 Split T18 into T18a to T18e

Date: 2026-11-01. Approved by: project owner (explicit request in the review session).

## Old value
Spec section 27: "T18 P0 playable gate, depends on T15 T16 T17. Files: AppFlow, PracticeRoom, onboarding, tests.
Done: two clients complete all moves; D02 D04 D08 on both iPads."

## Problem
At T15 the client renders nothing (`apps/client/src/main.ts` is 21 lines). GameScene, FighterView, Lobby, AppFlow,
KeyboardRouter and the HUD wiring from the section 18 tree have no owning task before T18. As written, T18 would be
several thousand lines, against the section 27 limit of about 500 changed nonasset lines per task. The first visual
playtest, which section 27 wants "early enough to adjust control spacing", would come only after all 16 moves.

## New value
| Task | Title | Depends on | Done means |
|---|---|---|---|
| T18a | Scene and fighter views | R01 T05 | GameScene and FighterView with original geometric placeholders; island colliders rendered from islands.v1.json; remote fighters interpolated from SnapshotBuffer; dispose() leaves zero renderer objects |
| T18b | Client input and prediction loop | T18a R08 R14 | PointerRouter and KeyboardRouter feed IntentSampler and RoomClient at 30 Hz; local Prediction and CameraRig run on the frame loop; Playwright drives a full match between two browser contexts |
| T18c | App flow, lobby and HUD | T18b T14 | Section 6 journey: boot checks, Welcome, invite exchange, fighter select, Ready, five error states; Hud bound to replicated hp, cooldownEndTicks, meter and form |
| T18d | Practice room and onboarding | T18c T17 | PracticeRoom with dummy and toggles, meter disabled; tutorial steps confirmed by the server |
| T18e | P0 playable gate | T15 T16 T17 T18d R12 R13 | Two browser clients complete all 16 moves and both awakenings; D02 D04 D08 run on both iPads by a person, or recorded NOT RUN |

## Reason
Keeps each task reviewable, gives every section 18 client module an owner, and brings the first visual playtest
forward to after T18b (eight moves playable) instead of after T17.

## Impact
- Protocol and content hash: none.
- Moves affected: none.
- Downstream dependencies on "T18" now point to T18e.
- Tests: section 25 and 26 IDs are unchanged and stay assigned to T18e.
