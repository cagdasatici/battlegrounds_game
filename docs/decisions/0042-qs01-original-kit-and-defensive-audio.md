# 0042 QS01 original kit and defensive audio (delegated design calls)

Owner delegated design decisions to the orchestrator (decision 0033). Audibility judgments below come from offline-rendered buffers and are delegated, not a human sign-off. Physical iPad audibility is QD01.

1. Element identity, all synthesized from oscillators and filtered noise (no samples). Stone: sine thud 90 to 50 Hz plus low noise, then three short band-passed chips at 100/170/240 ms with falling cutoffs (2.6, 2.0, 1.5 kHz). Tide: a 160 ms band-pass noise sweep 300 to 2400 Hz, then a descending sine 820 to 330 Hz. Ember: sawtooth charge 160 to 820 Hz with a 150 ms attack, then at 300 ms a dry high-passed crack with a crackle LFO and no low tail. Block, counter, KO, hit and heal recipes are unchanged except block gain raised (0.25/0.3 to 0.4/0.45) because its first render was the quietest (RMS 0.005).
2. Sustained beds. Only abilities whose Active phase is at least 30 ticks (SUSTAIN_MIN_TICKS) and whose id is a kit move (sv/td/ea, not m1 or dash) get a bed, one per element (LOOPS: low rumble, bandpassed water hiss, sawtooth drone with crackle). The bed is driven from replicated state once per animation frame (action Active, replicated actionStartTick/actionEndTick and serverTick), keyed `entity:startTick`. It stops when the tick reaches actionEndTick, when the action is no longer Active (interruption, death), when the entity leaves the player map, when the page is hidden (visibilitychange, pagehide), and when the AudioContext leaves "running" (statechange, covers iOS "interrupted"). Audio never schedules or decides damage.
3. Voice cap. A loop is a voice: it counts toward the existing 16 voice cap, uses the same steal rule, and is attenuated by distance each frame (out of 45 m it stops). The local fighter's own bed is top priority.
4. Unlock. Gesture listeners (pointerdown, touchend, keydown) stay attached until the context reports running, so a Safari context left suspended on creation is resumed by the next touch. Because the Play press happens before the match scene attaches Sfx, attach also unlocks immediately when `navigator.userActivation.hasBeenActive` is true (an earlier intentional interaction). Nothing plays before a real gesture.
5. Dedupe. CombatBus already dedupes by eventId; Sfx adds its own 512-entry ring because audio must not double-trigger if a listener is ever attached to a source that does not dedupe.
6. Settings. The existing effects volume is the only audio setting and is re-read on every event and frame. No music volume exists in this build; QD01 checks audibility with and without music if music is added. Not invented here.
7. Debug probe. Sfx exposes a read-only `globalThis.__ebAudio` object holding the live bus so the browser spec can count voices; it is removed on teardown. Acceptable for a presentation module with no secrets; revisit if a production-only build gate is added.
