# gr-GR03: connection and page lifecycle (D, local design choice)

- `ConnectionLifecycle` (pure, `apps/client/src/app/ConnectionLifecycle.ts`) owns the SDK subscriptions (`onDrop`, `onReconnect`, `onLeave`, welcome) and their unsubscribe handles. Phases: `connecting`, `active`, `reconnecting`, `closed`. `active` needs a new welcome, an owner snapshot carrying that welcome's epoch, and (in a match) the authoritative `ready` flag. Until then the GameLoop gate is closed: no sampling, no sending, no local prediction, queued edges discarded.
- The SDK's own automatic reconnection (installed @colyseus/sdk 0.18.9, `room.reconnection`) is kept; the client never issues another ticket or seat on a drop. Offline buffering stays off (`maxEnqueuedMessages = 0`).
- Terminal close mapping: 4401 session ended, 4500 arena closed (Back only), every other unexpected close "Connection lost" (Retry for ordinary rooms, Back only for sparring where the match is gone). Always an explicit error route; no silent rejoin or reset. This changes the earlier behaviour where a closed hosted match returned a guest straight to Welcome; two browser assertions were updated to click Back.
- Reload recovery: `sessionStorage` holds the reconnection token (`eb.reconnect`) and `{roomCode, mode, host}` (`eb.reconnect.meta`). Boot tries `tryResume` exactly once before normal entry, reconnecting first and loading assets afterwards (the seat is reserved for only 20 s). A rejected resume discards both keys and shows Welcome. An invitation token is never reused.
- `pagehide` is a suspension: the socket is closed without consent (code 4010) so the server keeps the seat reserved, SDK auto-reconnect is disabled in the dying page, and the token survives. Explicit Leave/Back is the only path that clears it. `pageshow.persisted` rebuilds through the ordinary boot (serialized, one session at a time).
- Limitation (documented, not hidden): if asset loading fails after a successful resume the room is left and the seat expires after the 20 s window.
