Date: 2026-11-01. Branch wave3-r18 on 71be8ea. Files: tests/fixtures/LatencyProxy.ts, tests/integration/latency-matrix.test.ts (port 25716). No production code changed, no dependency added.

## Method
- `LatencyProxy` is an in-process TCP proxy (Node `net`, as the packet allows; tc/netem was not needed). Each chunk is delayed by RTT/2 plus uniform jitter in [0, J] (seeded PRNG), and delivery times are clamped non decreasing per direction, so byte order is never broken. Loss and reordering are not simulated.
- Only the WebSocket goes through the proxy. Login and ticket HTTP go direct. All seats are real RoomClient connections.
- Scenarios: A01 (two clients, distinct entity and life ids, identical views and HP), A07 (same sv.b3 skillDown edge sent 10 times plus a stale epoch packet: one cast, 7 HP), A08 (two td attackers tap td.b1 on the same victim at once: victim loses exactly one capture, 24 HP, no stuck capture), A20 (drop, reconnect, then an old epoch skillDown/skillUp arrives: no cast, no damage).
- Each condition returns a signature of authoritative results and must equal the 0 ms proxy run (same HP, same cast counts, no duplicates). Invariant violations must be empty.
- Columns below are measured by the proxy during the run: mean and max one way delay actually applied, and chunks forwarded. Wall time is the scenario duration.

- The 0 ms baseline also runs through the proxy.
