## Known interplay (stop-and-report item for the owner of GR00)
Closing a tab mid-match is now a suspension: the seat stays reserved for the server's 20 s window (the spec's reload/BFCache requirement; a reload cannot be told apart from a close at pagehide). Specs that assume `ctx.close()` frees the seat immediately are affected:
- `tests/browser/p0-gate.spec.ts` (GR00-owned, NOT edited): picks its room with `r.clients === 2`, so it can pick the previous test's still-reserved room. In a `-g`-less run of that file, 9 of 18 tests (every second one) failed: `sv.b4, sv.a2, sv.a4, td.b1, td.b3, td.activate, td.a2, td.a4` and one more. Fix belongs to GR00: select the room by code (`roomDirectory.get`) or leave explicitly (`tests/browser/harness/leave.ts`).
- `telegraphs.spec.ts` and `quality-skills.spec.ts` now close contexts through the new `tests/browser/harness/leave.ts` (explicit HUD Leave first). After that: telegraphs QV02 passed, quality-skills 5 of 7 passed; QV07 low and medium still fail, which is the pre-existing GR00 baseline failure (trail peak 8, expected greater than 8).
- Other specs that share a room code after closing contexts (`match`, `projectile`, `urn-views`, `ux11-nameplates`) were not changed; ux11 passed. Full `pnpm test:browser` run once on this change: 123 passed, 19 failed, 1 skipped (40.8 min): 9 p0-gate and the QV06/QV08/QV02 cases above (since fixed), plus pre-existing QC01 and QV07 x2. `art.spec` play-clips, `hitfx.spec` flash, `onboarding-flow` replay and `quality-load` geometry failed in the full run only and passed when run alone (timing/load; another session was also using this machine). A full browser re-run after the final edits was NOT run.
