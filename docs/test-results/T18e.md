## What was added
- `tests/browser/p0-gate.spec.ts` (18 tests, workers 1, same harness as match.spec.ts: in-process Colyseus server, real client served by Vite, same origin).
  One fresh room and two fresh browser contexts per row. Row names: sv.b1 to sv.b4, sv.a1 to sv.a4, sv.activate, td.b1 to td.b4, td.activate, td.a1 to td.a4
  (16 slotted moves plus both awakenings).
- Input is real UI only: base moves by `touchscreen.tap` on the HUD controls (`[data-control=skillN]`, `awaken`), awakened moves by keyboard (Digit1 to Digit4, KeyG).
  The awakening that precedes an awakened row is a touch tap on the Awaken control (sv.activate uses touch, td.activate uses KeyG).
- Assertions read only replicated state through `window.__eb.snapshot()` on both clients: the victim HP sequence seen by the caster client equals the one seen by the
  victim client, final HP equals the R12 number, expected victim actions (Stunned, Ragdolled) were seen by both clients, the caster client saw the move id, the
  caster form is Awakened on both clients for the activation rows, no console or page errors, server `combat.invariantViolations()` empty.
  Kill rows (sv.a1 to sv.a4) require both clients to see HP 0 and action Dead. td.b2 additionally asserts the wall stop position.
- Expected numbers are the R12 rows (docs/test-results/R12.md). Raw per-row traces: `docs/test-results/T18e-playwright.json` (written by the spec).

## Server fixtures used (documented as required)
Only two, both the same as tests/integration/kit-matrix.test.ts, reached through the in-process room object (`matchMaker.getLocalRoomById`):
1. Placement: `room.movement.get(id).rb.setTranslation/setNextKinematicTranslation` plus `state.facingYaw` (both fighters in the clear central area, A on the +Z side of B so the default camera yaw 0 faces B; td.b2 uses x -10, z 1.0 beside wall.0).
2. Awakening meter pre-fill: `room.combat.get(id).meter100 = 35000`.
Damage, hits, forms and results are never injected. The spec waits for spawn protection to end (`protectedUntilTick`) before each row.
Limitation: because the fixtures use the in-process room, the spec cannot run against a remote server. The camera is never turned (yaw 0 only), so aim by camera drag is covered by match.spec.ts only.

- Performance of SwiftShader rendering says nothing about iPad frame rate.
