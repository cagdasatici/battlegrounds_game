# T27 test report (settings and layout editor)

Date: 2026-11-01. Node v22.23.4 (repo wants 24.22.2; engine WARN only). Decision: docs/decisions/0013-t27-settings-and-layout-rules.md.

## What changed
- `apps/client/src/app/SettingsStore.ts` (new, pure): schema v1, strict hand-written validator (unknown keys, wrong types and out-of-range
  numbers rejected at every level), 8192 byte export/import cap, per-profile persistence under `eb.settings.v1.<label>`, corrupt/oversized/
  wrong-version stored data falls back to defaults, throwing storage tolerated, `subscribe` with unsubscribe.
- `apps/client/src/input/LayoutEdit.ts` (new, pure): viewport class (wide at 900 CSS px), normalized per-control position and size
  (0.85 to 1.30), opacity, left hand mirror, `editControl` (rejects overlap, unsafe position, bad range), `resolveLayout` (falls back to
  defaults when a stored layout is unsafe at the current viewport).
- `apps/client/src/ui/Settings.ts` (new): settings panel (sliders, toggles, quality, export/import, reset) and the drag layout editor.
  Delegated listeners only, all removed in `dispose()`; `open()` calls a hook that releases held inputs; panel keys do not reach the game.
- Wiring: `Lobby` Settings button (Welcome), `Hud` menu Settings button, `main.ts` (store per Arel/Nora label, layout/handedness/camera
  speed/camera distance/initial facing lock applied, panel closed on leave), `PointerRouter.sensitivity` multiplier.
- No server, protocol, content hash or combat code changed.

## Bug found while testing
A `keydown` stopPropagation on the panel root swallowed Esc when focus stayed on a just-hidden panel button (flaky, 1 in 3 runs). Fixed:
propagation stops only while the panel is open, and closing blurs panel focus. 10 consecutive reruns of the in-app test passed afterwards.
