## Coverage added (tests/integration/sparring.test.ts, "QA01" test)
Host and guest, real Colyseus clients, real input packets:
- **Simultaneous hits.** Both fighters press M1 on adjacent packets. The spec (decision at docs/spec.md around line 745) says same-tick ties resolve in damage-resolver order and trades are not promised, so the test asserts exactly one side takes damage and both clients agree on HP. This is deliberate, not a defect.
- **Reconnect during a cast.** The host socket drops mid-cast; the seat is retained (same entity id, no duplicate fighter), the cast still resolves, and the guest sees the host connected again.
- **KO agreement.** Both clients read the same kills and deaths.
- **Leave and rejoin.** The guest leaves, its scope returns 401, and a fresh single-use link admits a new guest with zero kills, zero deaths and full HP.
- **Host ends, rematch.** The host ends the match, the guest scope is dead, the same host starts a new match under a new room code, and every score is zero.
Already covered by existing tests and left untouched: mixed bots, KO and respawn without score bleed, host reconnect, explicit end and rehost.
