# QV05 Furnace Ray signature

Base SHA: 2b05828. Node v24.22.2, pnpm 10.28.0 (an early browser run under Node 26 was discarded). Chromium via SwiftShader, 1024x768, effective tier low.

## Changed behavior
- `apps/client/src/fx/kits/ea.ts`: ea.a3 gets `playFurnaceRay`, a sustained emitter. While the replicated action is Active it redraws every 3 ticks along the current aim: a thin bright core (8 small gold-white particles) inside a tapering orange sheath (8 larger particles, half-width 0.61 m at the muzzle falling to 0.06 m). Length = min(24 m, client cover query from the beam origin), the same query the warning uses, so the beam stops at cover.
- Pulse highlights: a gold flare (8 particles, 0.25 s) fires once for each pulse tick activeStart + hitOffsets[i] (0,15,...,89, read from the ea.a3 definition) once the replicated server tick reaches it.
- End: emission runs only while the replicated action is Active and tick < actionEndTick. Interruption, death or active end stops it on the next frame; leftover particles live at most 0.1 s (flares 0.25 s).
- Shared change (outside the row's file list): `fx/kits/common.ts` gains optional `Recipe.sustain`/`sustainPeak` (counted in `recipeParticles`), `SustainCtx` and `scanSustain`, run per frame from `makeKitFx` with `deps.serverTick`/`deps.cover`; per-actor state is dropped when Active ends or the actor leaves, and cleared on detach. Without a replicated tick nothing is sustained. Recipes without the hooks are unchanged.
- Root-cause fix found by the new browser case, in `scene/EffectsPool.ts`: the pool's live counter drifted, leaving `activeCount` stuck at 16/32 with no live slot (observed via internal state), so particles never reported drained (also the likely cause of one earlier QV04 browser timeout). `update` now recounts live particles each frame and sets a dead slot's age exactly to its life. The regression unit test passes with and without the fix, so it is a guard, not proof; the browser case went from failing in most runs to 4 of 4 passes.
- Presentation only: no timers, no damage or movement scheduling. Warning (AttackTelegraphs) untouched.

## Source mapping (ea.a3)
Config `ea.a3`: startup 30, active 90, hitOffsets [0,15,30,45,60,75,89], beam length 24 radius 1, block B. Handler furnaceRay (apps/server/src/kits/ea/beams.ts): pulses at activeStart + offset, beam re-clipped at first solid obstacle, cast ends on interruption/death/capture. Client: actionStartTick in Active equals activeStart, actionEndTick equals activeEnd.
