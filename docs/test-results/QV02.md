# QV02 Durable attack telegraphs

Base SHA: e3938e3. Node v24.22.2, pnpm 10.28.0. Chromium via SwiftShader (software WebGL), 1024x768, effective tier low.

## Changed behavior
- New `apps/client/src/fx/AttackTelegraphs.ts`: a pool of 6 retained warning slots (flat fill plus outline), separate from the FX1 particle pool. Wired through `registerPresentation` (`fx/index.ts`) with new optional deps `serverTick`, `cover`, `onTelegraphs`; `main.ts` supplies the replicated tick (clock estimate, floored), cover clipping and a debug snapshot `telegraphs` (plus test-only `floodFx` and renderer `geometries`).
- Warned moves: sv.b1, sv.b2, sv.a2, sv.a3, td.a3, ea.b1, ea.a3, ea.a4. Shape and reach come from the ability definition (box forward span [0,d], sphere centred `range` ahead, beam from 0.6 m ahead). Beams are clipped at cover with a horizontal ray test against map colliders (cylinders use their bounding box, slightly conservative; server uses Rapier).
- Keyed by actor, life, move and actionStartTick. Windup to Active of the same cast and life transfers the slot and committed origin; anything else (interruption, death, expiry via replicated actionEndTick, leave, new life, new move) removes or replaces it. Progress is derived from replicated ticks. Aim follows replicated facing only for moves with turnRate.
- Nothing is drawn before the server replicates the cast (also for remote players). A first sighting in Active draws only the Active warning; no retroactive Windup (verified through `history`).
- Low quality and Reduced Motion keep the outline and use a static fill.
- When all slots are busy a new warning is refused and counted (`dropped`); existing warnings are not evicted.
