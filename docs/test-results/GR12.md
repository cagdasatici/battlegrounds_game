# GR12 Clear entry routes and fighter preview

Baseline commit: ff105dd (GR00/FR01 files and `tests/browser/p0-gate.spec.ts` untouched). Node 24.22.2, pnpm 10.28.0, `--workers=1`.

## Changed
- `ui/Lobby.ts`: Welcome card is primary **Play with friends**, secondary **Practice** and **Fight bots**, then **Find a room**, **How to play**, **Settings**, small Admin link. Profile caption `Choose the name shown in the arena.`; the invitation sentence is gone (the existing `INVITE_INVALID` error text is unchanged and only appears when that flow fails). Fight bots and Find a room are hidden for a guest who arrived by sparring link (as the old launchers were). Lobby shows three fighter cards with the verbatim role and tip, the four base-move names, the guide link and Ready. Controls are disabled and `aria-busy` while an entry action runs.
- `app/AppFlow.ts`: `FlowState.busy` (`preparing` while runtime and map load, `joining` during login and network join) for Play, Practice, listed-room join and Host sparring; cleared on success, error, Back and dispose. Errors keep the existing Retry/Back controls. No byte progress.
- `main.ts`: Fight bots and Find a room open the existing sparring setup and room list from Welcome. The floating launchers are removed on Welcome; the floating button remains only as the in-match "Sparring controls" action. The lobby preview is drawn from the existing idle loop (selected by flow screen, since a joined lobby already holds match cleanups).
- New `ui/FighterPreview.ts` (220x200 CSS px reserved region, kit intent, reduced-motion switch) and `scene/GameScene.ts` (`setPreviewKit`, `renderPreview`): one preview fighter in a small private scene, drawn by the already-loaded renderer into a scissored viewport. No second `WebGLRenderer`. `LobbyPreview.ts` (the old second renderer) is deleted. The preview fighter is disposed on leaving the lobby, entering a match, and scene dispose. Reduced motion (OS preference or the saved setting) holds the pose still.
- `experience.css`: card, mode-row, more-row and preview rules; lobby screen background is transparent so the shared canvas shows through the preview region.
- `SparringSetup.ts`: unchanged (defaults already one medium bot, endless rounds; asserted by test).
