# T18b test report (client input and prediction loop)

Date: 2026-11-01. Node v22.23.4 (repo wants 24.22.2; engine WARN only).

## What changed
- `apps/client/src/app/GameLoop.ts` (new): one rAF loop. Local Prediction steps once per estimated server tick (integer ticks, 60 Hz,
  never from render dt), real Rapier collide (R14). Intent packets go out at 30 Hz; edges and digital hold changes go out
  immediately inside a client token bucket matching the server (45/s, burst 15). Owner reconcile only when the replicated
  `ackInputTick` advances (or life/action changes); anchor is the ack. Remote fighters feed SnapshotBuffer only when
  `state.serverTick` advances. CameraRig follows the predicted mesh pose. No damage/hit/target field is ever sent.
- `apps/client/src/input/KeyboardRouter.ts` (new): WASD, mouse attack, F, Q, Space, 1-4, G, Shift, Esc (spec section 11).
- `PointerRouter`: `hasEdges`, `keyHold`, `setKeyboardMove` (keyboard shares the touch router state).
- `main.ts`: with `#invite=...` (fragment only, removed from the URL) logs in, joins `?room=`, sends ready, binds
  PointerRouter + KeyboardRouter + Hud + GameLoop; every listener, timer and the room has cleanup on pagehide. Without an
  invite the T18a static arena still shows. `?debug=1` exposes a read-only `window.__eb.snapshot()` for browser tests.
