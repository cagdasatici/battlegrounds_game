# QV04 Undertow Spiral signature

Base SHA: f73c109. Node v24.22.2, pnpm 10.28.0. Chromium via SwiftShader, 1024x768, effective tier low.

## Changed behavior
- `apps/client/src/fx/kits/td.ts`: td.b2 gets a confirmed-hit reaction, `playUndertowHit`. On the first bus `hit` with moveId td.b2 (the capture, +0) it spawns 20 particles: a narrow bright cyan leading edge (6) and a darker curved ribbon (14, bowed sideways, trailing the edge). All move 3 m over 0.6 s (the server's 36 tick drag) away from the caster, starting at the victim, then expire by life.
- The second `hit` from the same actor within 60 ticks (the slam, +48) uses the recipe's generic splash instead of another ribbon.
- A miss or block emits no `hit` (only `hit` is handled), so no victim-bound ribbon or impact is drawn. Windup ring and caster-side Active spiral are unchanged.
- Small shared change (outside the row's file list, in its spirit): `fx/kits/common.ts` gains optional `Recipe.playHit` and `Recipe.hitCount` (counted in `recipeParticles`); `onHit` passes the actor chest position. Recipes without them behave as before.
- Presentation only: durations are particle life; no timers, no damage or movement scheduling. Module state `firstHitTick` is bounded (32 entries) and cleared per slam.
- Tests: `tests/unit/fx-td.test.ts` (4 new QV04 tests), `tests/browser/quality-skills.spec.ts` (new QV04 case in the existing spec).

## Source mapping (td.b2)
Handler dragSlam (apps/server/src/kits/td/dragSlam.ts): hits at +0 (5) and +48 (14), pair moves 3 m over ticks +1..+36, release +49. Impact/capture events = bus `hit` with moveId. Ribbon direction = caster to victim on the ground plane.
