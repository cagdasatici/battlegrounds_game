# QV01 Visible urn lifecycle

Base SHA: d76851c. Node v24.22.2, pnpm 10.28.0. Chromium via SwiftShader (software WebGL), 1024x768, effective tier low. Desktop software FPS is diagnostic only.

## Changed behavior
- New `apps/client/src/scene/UrnViews.ts` renders the replicated `UrnSchema` records keyed by id (centimetres converted with fromCm).
  - anchored: squat ochre vessel at the anchor.
  - reserved: pulsing glow ring on the remembered anchor (the server publishes the holder pose in reserved/held records, so the true anchor is remembered from the anchored record).
  - held: vessel beside the visible holder's hand (offset from the interpolated fighter group), re-placed every render frame after remote interpolation.
  - returning: hidden until the server republishes anchored.
  - missing, dead or hidden holder: vessel hidden. Removed records, GameLoop dispose and scene dispose remove meshes and dispose geometry and materials.
- Wired in `GameScene.ts` (`urns`, update, dispose), `GameLoop.ts` (sync from replicated state, clear on dispose) and `main.ts` (state read plus debug snapshot).
- GameLoop now materializes `st.players` once per frame; it is a one-shot iterator and the first attempt consumed it (caught by the ORB2 regression spec).
- No throw streak is drawn: UrnSchema publishes no throw endpoints (plan: omit when unavailable). The thrown flight remains the server projectile. Touch input never reserves an urn or infers damage.
