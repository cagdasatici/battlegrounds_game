The numerical targets below are local design decisions (D).

## Session contract

1. Use the repository root. All paths below are exact relative to it. In a fresh session run `git status --short --branch`, `git log -1 --oneline`, `node -v`, `pnpm -v`. Require Node 24.22.2 and pnpm 10.28.0. On the project Mac, prepend `$HOME/.local/node24/bin` to PATH if present, then recheck. Use the committed lockfile. Stop on unavailable runtime, missing prerequisite implementation, or uncommitted changes in an owned path. Never stash or clean another lane's work.
2. Default to the ledger dispatch order, one ID per session. A predecessor with implemented desktop evidence and pending device acceptance unlocks desktop work. QD01 and QR01 require the physical evidence specified below. Use the explicit dependency column in the ledger. If separate executors work concurrently, give them independent worktrees and merge one slice at a time. Serialize shared camera, rig, FX, HUD, manifest, build and ledger writes. Re-run the common gates after integrating onto the current head.
3. The scope for every row includes its report and ledger row. Each listed unit or browser test is an owned test path. Existing production files outside the row are read-only. A listed new file may be created. For an unlisted production dependency, failing baseline unrelated to the slice, shared schema change, unavailable reference asset, or missing host permission, stop and report the file, failing command and minimum proposed follow-up. Do not weaken an assertion or invent authority to get green.
4. Preserve spec authority, server decisions, fixed 60 Hz integer ticks, existing ability definitions, map collision, auth scopes, reduced-motion behavior and original fighter identity. Cosmetic interpolation may read server time. Rendering must never decide hits. Keep original game claims in research with evidence IDs. Use no new packages. Use the existing CC0 exception only for environment dressing. Every visual must dispose on removal, leave, reconnect replacement and final teardown.
5. Every code row runs these **common gates**, locally and serially. All required fixture servers bind loopback. Q00 and QR01 additionally run the full browser suite. Do not run another load-sensitive suite during a measured run.

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
git diff --check
```

For art or data changes also run `pnpm content:validate` and `pnpm assets:audit`. For generated art run `pnpm assets:build` before those checks; run it twice and verify identical output. The permitted generated outputs are `assets/fighters/sv.gltf`, `assets/fighters/td.gltf`, `assets/fighters/ea.gltf`, `assets/manifest.json`, and `assets/provenance.csv`. Only commit outputs whose source or manifest inputs changed. The manifest hashes ArenaView.ts. Use the generator for arena changes too. Correct the generator if its provenance statement would be false for an added file.

6. In slice entries below, **U** means run `pnpm exec vitest run` followed by the listed paths and **B** means `pnpm exec playwright test` followed by the paths. A bare U name expands to `tests/unit/<name>.test.ts`; a bare B name expands to `tests/browser/<name>.spec.ts`. An integration path uses the U command. Substitute sv, td or ea literally for K. A title filter uses `--grep <ID>`. **Art gate** means both asset checks, the medium overview at both viewports and the Q01 canonical fight on low and medium. **Fight gate** means the Q01 fight from both clients, with real input and server outcomes. Store retained artifacts in `docs/test-results/<ID>/`. Let legacy browser tests write in an isolated checkout to avoid overwriting historical evidence.
7. Report the base SHA, Node/pnpm, commit subject, exact commands/exits, device or renderer, viewport, quality, before/after evidence, failed attempts and remaining NOT RUN rows. Keep invite fragments, session IDs, tokens and personally identifying data out of reports. Commit only owned files. Use the subject in backticks for each ID, then a ledger-only commit to record the implementation SHA. Follow repository push instructions. No automatic deployment. A missing physical check is IMPLEMENTED, DEVICE CHECK PENDING for a finished code slice. A missing required dependency is BLOCKED with its name.
8. If a prescribed visual misses a gate, make one adjustment inside the slice and repeat the failing check. If it still fails, leave the slice IN PROGRESS with the two captures and failing metric. A gameplay rule conflict goes directly to stop-and-report under the authority order. A reproducible defect spanning two ownership areas gets a named follow-up and stays open at release.

## Evidence contract used by every lane

**Shots.** Use landscape 1024×768 and 1180×820; capture at default gameplay distance and FOV. Capture low and medium separately and record the *effective* tier. Software rendering pins the normal client to low. Use the existing art harness for commanded medium captures and label them as harness evidence. Use hardware for true medium gameplay acceptance. Save the same viewpoint, heading, kit, arena location and tick offset for before and after. Include the attacker's rear view and defender's rear view. Include one HUD-visible take and one diagnostic take without combat text. Use the live HUD in usability and performance tests.

**Four-fighter workload.** One ordinary host, one human-equivalent guest and two legal server bots on the main island. Both browser contexts join through existing auth. Use deterministic test-only setup for spawn, meter and cooldowns; then drive combat through validated input. In the measured interval require two distinct overlapping awakened fighters, a confirmed hit, block, dash, projectile reflection and KO. Record event counts; a quiet server or static scene is an invalid run. For the physical stress run the owner operates both clients with two bots. Compare pre/post client resource counts after a leave and rejoin.

**Run record.** Write one JSON object per distinct workload/build/tier. Nullable fields are mandatory. Use null plus a reason for an unavailable metric. Keep numeric values unrounded in the raw file. This is a reporting format, never a multiplayer message.

```json
{"buildSha":"","workload":"","device":"","os":"","browser":"","renderer":"","tier":"","viewport":[1024,768],"durationSeconds":0,"sampleCount":0,"medianFps":null,"frameP95Ms":null,"maxConsecutiveBelow30Seconds":null,"maxDrawCalls":null,"maxVisibleTriangles":null,"heapSteadyMB":null,"heapGrowth10JoinsMB":null,"events":{"overlapAwakening":0,"hit":0,"block":0,"dash":0,"reflection":0,"ko":0},"evidence":[],"unavailable":[]}
```

**Performance gates.** Spec §24 governs: on each actual iPad, 10 min ordinary play median ≥55 FPS, p95 frame ≤25 ms and no continuous interval below 30 FPS longer than 3 s. Four-fighter low stress p95 ≤33.3 ms over 5 min. Medium peak ≤120 calls and ≤150,000 visible triangles. Heap ≤150 MB where measurable and growth ≤20 MB over ten joins; if Safari lacks heap, record unavailable, counters, ten cycles and crashes per §24. Pixel budgets low/medium/high ≤0.75/1.5/2.5 million; scale 0.6–1.5. Cold compressed shell ≤1 MB, playable P0 ≤15 MB, full P1 cache ≤35 MB. Server tick p95/p99 ≤4/8 ms; no backlog beyond 3 callbacks. Per-player steady upstream/downstream ≤8/30 KB/s and bursts ≤80 KB/s over 1 s. Highlight within one frame, confirmed action p95 <100 ms LAN and <200 ms remote at RTT ≤120 ms. Record compression, cache state, transport overhead and hardware. Desktop software FPS is diagnostic only.
